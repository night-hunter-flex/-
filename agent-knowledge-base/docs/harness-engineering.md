# Agent Harness 工程

Harness 把动作选择放进可控的执行系统。本文是本库的工程建议；持久执行与人工介入可参考 [LangGraph](https://github.com/langchain-ai/langgraph)，规划、文件与委派的组合可参考 [Deep Agents](https://github.com/langchain-ai/deepagents)。核验日期：2026-10-10。

## 最小职责

| 环节 | 输入与输出 | 检查点 |
| --- | --- | --- |
| 接收任务 | 目标 → 任务契约 | 输入是否齐全、成功条件是否可验证 |
| 准备上下文 | 状态与证据 → 当前调用输入 | 数据来源、权限、大小与时效 |
| 选择动作 | 模型结果 → 结构化动作 | 工具名、参数类型、必填字段 |
| 执行工具 | 已校验动作 → 工具观察 | 权限、超时、预算、幂等性 |
| 更新状态 | 观察 → 新状态与运行事件 | 失败类型、已完成事实、待办 |
| 验收与停止 | 产物与证据 → 明确状态 | 完成、失败、预算耗尽或等待人 |

仅在提示词中写“最多执行几次”，不能代替程序中的预算检查。

## 状态需要哪些字段

下面是应用状态示意，不是某个框架的 API：

```json
{
  "task_id": "task-001",
  "status": "running",
  "goal": "整理指定目录中的资料",
  "completed_steps": [],
  "pending_steps": ["读取资料", "核验引用", "生成草稿"],
  "artifact_paths": [],
  "evidence_refs": [],
  "budgets": {"tool_calls_remaining": 20},
  "checkpoint_version": 1
}
```

用户约束与已观察事实分开存储。摘要可用于压缩上下文，但原始证据应有可定位的引用，不能把“计划做了什么”写成“已经完成什么”。

## 预算与重试

至少分开限制决策步数、模型请求数、工具执行次数和总耗时；模型成本另设额度。每次调用前扣减或预留预算，并记入事件。并行执行时使用共享计数或原子预留，避免每个工作者各自消耗一份完整总预算。

| 错误 | 建议处理 | 不宜直接做什么 |
| --- | --- | --- |
| 限流、临时连接失败 | 有界退避，遵守服务返回的等待要求 | 无限即时重试 |
| 参数或 schema 错误 | 返回结构化错误，允许有限修正 | 对同样参数反复调用 |
| 权限拒绝 | 停止动作，记录所需授权 | 更换工具绕过权限 |
| 数据缺失或证据冲突 | 补检索、澄清或给出明确局限 | 编造成功结果 |
| 有副作用的请求超时 | 查询提交状态或幂等键 | 假定失败后重复提交 |
| 策略重复相同动作 | 检查是否新增观察，设置循环终止 | 只提高最大步数 |

是否可重试由工具契约与错误分类共同决定。幂等的计算、查询和会产生订单/消息的操作，需要不同恢复策略。

## 检查点与副作用

在外部写入前记录动作意图、参数摘要和幂等键；提交后记录远端回执。恢复时先核对外部真实状态。若工具不支持幂等且无法查提交状态，将任务转交人工处理。

“恢复运行状态”不等于“任意外部操作恰好执行一次”。文件写入可先生成临时文件再原子替换；业务操作依赖服务端事务、幂等机制或补偿动作。最终使用哪种方案需按工具验证。

## 上下文管理

- 保留用户目标、最新约束、工具定义、当前计划和与下一步相关的证据。
- 对长工具结果做长度限制、分块或引用，保留原始数据位置。
- 摘要明确区分事实、假设、未完成步骤和待确认事项。
- 长期记忆带来源、更新时间与用户边界；支持纠错和删除。
- 恢复后重新读取可能变化的文件或远端状态，避免基于旧快照写入。

## 可观测性

建议记录 `task_id`、步骤、工具名、脱敏参数摘要、耗时、结果状态、重试、预算余额和产物引用。记录必要的决策摘要，不记录密钥或模型的隐式思维链。

[OpenAI 官方追踪说明](https://developers.openai.com/api/docs/guides/agents/integrations-observability)提供运行、模型、工具与交接的追踪入口；使用前确认追踪是否外发、包含哪些内容以及如何关闭或脱敏。
