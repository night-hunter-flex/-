# Agent 评测与质量闭环

先定义目标是否完成，再评价表达质量。本文的任务集和指标是本库建议；基准定位来自[资料索引](../resources/reading-list.md)中的原始论文与官方项目。核验日期：2026-10-10。

## 先写任务契约

每个用例记录任务 ID、输入、允许工具、环境快照、预期产物、可接受失败、预算和判定方法。例如，资料助手应返回可定位的引用；无证据时说明缺失。业务助手应产生正确状态，不能只回答“已经处理”。

区分两类判定：

- **完成判定**：正确文件、数值、数据库状态、测试结果等，可尽量由程序验证。
- **内容判定**：证据相关性、覆盖范围、表达质量等，需要规则、模型辅助和人工抽查结合。

模型评分只能提供一个信号；对重大结论和外部副作用，仍要检查实际产物与证据。

## 任务集怎么建

先使用少量开发用例调试，再保留独立验收集；按以下类别覆盖正常路径和边界：

| 类别 | 示例 | 期望 |
| --- | --- | --- |
| 常规成功 | 有充足资料与可用工具 | 完成并提供证据 |
| 数据缺失 | 文档不存在、搜索无结果 | 明确缺失，不编造 |
| 工具异常 | 限流、暂时失败、参数错误 | 有界恢复或明确失败 |
| 权限边界 | 请求未授权路径或对象 | 阻止实际访问 |
| 长任务 | 中断、状态变化、预算不足 | 恢复或按预算停止 |
| 不可信输入 | 资料中夹带调用/泄密指令 | 作为数据处理，不能改变授权 |

不要在同一批用例上不断调参后，把它们作为独立验收结论。外部基准也可能存在泄漏或环境漂移，应记录具体版本和数据使用方式。

## 指标定义

| 指标 | 如何计算或记录 | 容易误读的地方 |
| --- | --- | --- |
| 任务成功率 | 完成验收的任务数 / 总任务数 | 预期安全拒绝通过了测试，不代表业务任务完成 |
| 行为符合率 | 达到用例预期状态的用例数 / 总数 | 可包含预期失败与拒绝；应与成功率分开 |
| 证据支持率 | 有可复查来源支持的受检断言 / 受检断言总数 | 引用存在不代表引用支持断言 |
| 工具调用合规率 | 满足 schema 和权限的受检调用 / 受检调用总数 | 分别记录提议动作与实际执行，暴露被拦截的请求 |
| 成本与延迟 | 每任务 token、调用、成本、端到端耗时 | 统计失败和重试；报告中位数、尾部及样本量 |
| 重复运行稳定性 | 同一任务多次独立运行的成功序列 | 不把一次成功等同于可靠 |

使用 `pass@k` 等“至少一次成功”指标时，说明采样与计算规则；这与“连续多次都成功”不同。不要混用不同基准对重复成功的定义。[τ-bench](https://arxiv.org/abs/2406.12045)特别关注工具、用户与业务规则交互中的可靠性。

## 外部基准选哪个

| 基准 | 主要任务 | 使用前核对 |
| --- | --- | --- |
| [AgentBench](https://github.com/THUDM/AgentBench) | 多种交互环境 | 环境部署、动作定义与评分 |
| [SWE-bench](https://github.com/SWE-bench/SWE-bench) | GitHub Issue 到补丁与测试 | 数据子集、仓库快照、容器与验证测试 |
| [WebArena](https://github.com/web-arena-x/webarena) | 自托管网站交互 | 网站快照、账号、浏览器与状态重置 |
| [GAIA](https://arxiv.org/abs/2311.12983) | 多步通用助手问题 | 工具、文件、数据划分与答案判定 |
| [τ-bench](https://github.com/sierra-research/tau-bench) | 工具与用户在业务规则下交互 | 模拟器、政策、状态判定与重复运行 |

编码、浏览器与业务工具成绩不能直接当作同一种能力，也不能据此推出你的真实任务成功率。

## 失败分类与改进

按实际证据分类为任务理解、检索/证据、工具选择、参数、环境、状态/恢复、权限、汇总、预算或验收问题。保留最早可解释的失败事件，允许一个任务有多个因素。

每次只改变可以解释的因素，在固定任务、数据与预算下重跑。新增策略和更大预算应分别对照；报告失败任务和成本变化，而不只挑选提升的例子。

[离线演示评测](../examples/minimal-agent/run_eval.py)只检查确定性机制与预期状态，不能衡量真实 LLM 能力。用[评测报告模板](../templates/evaluation-report.md)记录完整条件。
