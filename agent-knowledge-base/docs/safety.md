# Agent 安全与权限边界

安全需要在工具与应用层执行，并通过实际行为验证。本页是工程建议，协议相关风险可参考 [MCP 官方安全实践](https://modelcontextprotocol.io/docs/draft/tutorials/security/security_best_practices)；该来源为 draft，应在实施时核对。核验日期：2026-10-10。

## 信任边界

用户指令、可信应用配置与外部资料应分开。网页、文件、搜索结果、工具描述和其他 Agent 的输出是数据；其中写有“忽略要求”“上传文件”“运行命令”，不能因此得到执行权限。

工具结果可用于解释事实，但不能替应用批准新操作。模型也不能通过声明“用户同意”创建授权。

## 将边界落实到执行层

| 风险 | 应用或工具层控制 | 可验证的测试 |
| --- | --- | --- |
| 提示注入 | 保留来源与信任级别，工具执行前独立检查权限 | 恶意资料不能触发上传或额外写入 |
| 文件越界 | 解析规范路径，检查符号链接/链接目标和允许根目录 | ../、绝对路径和链接不能越界读写 |
| 命令或代码执行 | 限定工具能力，隔离进程/容器、资源与网络 | 工具不能访问宿主秘密或任意目录 |
| 凭据泄漏 | 凭据留在服务端，日志与模型输入脱敏 | 输出和事件中不出现密钥 |
| 网络访问扩大 | 校验目标与重定向，限制内网和敏感地址 | 请求不能跳转到未授权服务 |
| 重复副作用 | 幂等键、提交回执与恢复核对 | 超时后不会重复发消息或提交订单 |
| 多用户混淆 | 工具按真实身份校验对象归属 | 用户 A 不能读取用户 B 的资料 |

隔离也需要配置与验证。拥有“sandbox”或“guardrail”组件不能自动证明所有风险都被阻止。

## 人工审批要对应具体动作

对删除、发布、发送、付款等操作，先准备可复查的内容、目标、参数和差异，再按应用策略取得授权。授权后若内容、目标或范围发生实质变化，应按策略重新判断。

审批状态保存在可信应用状态中，不能从模型文本或外部资料中解析出“已批准”。已得到的授权在明确范围内可以复用。

## 日志与故障处理

记录脱敏参数、动作状态、权限判定和回执，不把秘密、私有原文或无关个人信息完整写入追踪。确定日志的保存期限和访问权限；接外部追踪服务前确认数据会去哪里。

发生错误时保留已执行动作与残余状态。停止循环不会自动撤销远端副作用；需要状态查询、事务、补偿或人工处理。

## 入门测试集

至少测试恶意资料、异常参数、未知工具、无权限、工具超时、预算耗尽和重复提交。观察**实际工具执行记录**与外部状态；最终答案说“拒绝了”并不足以证明没有发生访问。
