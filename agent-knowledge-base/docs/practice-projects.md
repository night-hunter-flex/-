# Agent 实践项目

下面是四个逐步增加能力的练习。第一个已有离线运行代码，并提供一个独立的[真实 LLM 工具调用示例](../examples/llm-tool-agent/README.md)作为扩展；后三个是带验收标准的实现任务，不是现成应用。先提交复现记录，再增加复杂度。

## 项目 1：看清一次执行闭环

**目标**：运行[离线演示](../examples/minimal-agent/README.md)，理解动作、工具观察、重试和停止。

输入是算术表达式；确定性策略请求 calculator 工具，再根据观察结束。试验常规计算、除零、不允许的语法、首次暂时失败、步数不足和调用额度不足。

**验收**：运行回归用例；能解释每个事件；不支持的输入不会作为代码执行；失败和预算耗尽不会被包装成完成。

**扩展**：可从[真实 LLM 工具调用示例](../examples/llm-tool-agent/README.md)出发，把策略接口接到一个真实模型。保留工具注册表和执行校验，添加模型请求超时、成本预算与格式错误测试。记录模型、提示、工具 schema 和依赖版本，不能把离线测试成绩当作接入模型后的成绩。

## 项目 2：带证据的资料助手

**目标**：只读取指定资料目录，搜索并回答一个问题，输出来源路径与片段。

从关键词检索开始，后续再比较向量检索。工具返回文件版本、片段和截断状态；资料不足时明确指出，不让模型编造出处。

**验收**：

- 正常问题的关键断言均能定位到原始资料。
- 无答案或来源冲突有明确状态和说明。
- 不可信资料不能触发额外工具或扩大读取目录。
- 用户 A 的检索结果不能混入用户 B 的资料。
- 使用固定开发集与独立验收集比较检索策略。

参考：[工具与 MCP](tools-and-mcp.md)、[评测指南](evaluation.md)、[项目导航](../resources/github-projects.md)中的入门课程。

## 项目 3：可恢复的文件整理任务

**目标**：生成“原路径 → 建议路径”的计划和差异，确认后在测试目录应用。

限制任务根目录；先做 dry-run，再写入；记录意图、已执行步骤与回执。测试进程中断、目标重名、文件被外部修改和无权限。

**验收**：恢复后重新核对文件状态，不重复移动，不覆盖未知文件，不越过允许目录；无法判断已执行状态时停止并交接。用临时测试目录完成演练。

参考：[Harness 工程](harness-engineering.md)、[安全指南](safety.md)。完成本项目后，再测试框架的检查点恢复是否符合自己的副作用要求。

## 项目 4：资料收集与核验协作

**目标**：比较单 Agent 与“收集者 + 核验者”的资料整理过程。

两种方案使用同样任务、工具、资料快照和总预算。收集者提交候选来源与证据定位；核验者指出支持、冲突和未核实内容；汇总者保留不确定性。

**验收**：报告任务成功、受检断言的证据支持、端到端耗时和所有角色合计成本；保留分歧和原始证据。不因多个角色同意就认定结论可靠。

参考：[多 Agent](multi-agent.md)、[框架选型](framework-selection.md)。并行只用于独立子任务，同一产物的编辑明确责任人。
