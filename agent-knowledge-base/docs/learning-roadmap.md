# Agent 学习路线

这份路线按“理解一个 Agent 如何工作 → 搭建执行系统 → 评估结果 → 处理真实工程约束”逐步推进。

## 1. Agent 的运行闭环

先掌握一次任务执行中的基本过程：

```text
接收目标 → 获取上下文 → 选择动作 → 调用工具或生成内容 → 观察结果 → 判断是否继续
```

重点弄清楚模型、工具、状态和外部环境分别做什么，以及执行循环何时结束。

## 2. 常见决策方式

- **ReAct**：在推理与行动之间交替，根据工具返回的信息继续决策。适合需要边查边做的任务。
- **Plan-and-Execute**：先生成步骤，再逐步执行；必要时重新规划。适合目标较长、步骤可拆解的任务。
- **工作流**：关键路径由程序明确编排，模型负责有限范围内的判断或生成。适合稳定、可审计的业务流程。

比较它们时，观察规划成本、执行灵活性、失败恢复能力和结果可预测性。

## 3. 工具、上下文与记忆

学习工具的输入输出 schema、权限边界、超时和错误返回；理解上下文窗口如何限制任务长度；区分当前任务状态、会话历史和可长期复用的记忆。

## 4. Agent Harness

Harness 是围绕模型运行的执行系统。重点研究：

- 如何分解任务并跟踪每一步的状态
- 如何限制工具、时间、令牌和重试次数
- 如何保存检查点，并从中断处恢复
- 如何处理工具失败、结果冲突和不完整证据
- 如何让执行过程可观察、可复现、可审查

## 5. 评测与质量闭环

为任务定义可检查的成功条件，建立代表性测试集；记录最终结果与过程证据；对失败分类，修复后通过回归测试确认没有引入新问题。不要只用模型自评作为唯一质量信号。

## 6. 工程实践

从单 Agent、单工具的小任务开始，再逐步加入长任务、多工具、人工审批和多 Agent。每次增加复杂度时，都要说明它解决了什么问题，以及新增了哪些失败模式。

## 建议的学习产出

1. 画出一个 Agent 的调用时序图。
2. 实现一个带工具调用、超时和有限重试的最小 Agent。
3. 为一类真实任务设计成功标准和失败分类表。
4. 为长任务补充检查点、恢复和人工接管机制。

## 配套课程与先修知识

- 能读写基本 Python、异常与 JSON，即可运行离线演示；接模型前再学习供应商的工具接口、计费与限流。
- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：按设计模式完成课程练习，检查当前版本的框架和账号要求。
- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：结合[课程页面](https://huggingface.co/learn/agents-course/unit0/introduction)学习概念与工具。
- 增加能力时再查[GitHub 项目导航](../resources/github-projects.md)，不必先掌握所有框架。

每个阶段保留提交、命令、环境与原始观察；至少解释一个失败。用[复现卡片](../templates/project-card.md)和[评测模板](../templates/evaluation-report.md)记录证据。
